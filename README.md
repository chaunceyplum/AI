# 📘 RAG Application with Docker Compose – Architecture & Documentation

## 📌 Overview

This Retrieval-Augmented Generation (RAG) application enables intelligent querying over Snowflake documentation by leveraging a vectorized search pipeline and LLM-based answer generation. It is containerized using Docker Compose and deployed in a cloud environment. The app scrapes, indexes, stores, and queries documents through an orchestrated flow of microservices, all communicating via API endpoints.

---

## 🧱 Architecture Layers

### 1. **Cloud Hosting Environment**

- The entire Docker Compose application runs in a cloud-hosted infrastructure.
- MongoDB exists both inside and outside Docker Compose for persistent vector storage.

---

### 2. **Docker Compose Stack**

Encapsulates all services required for the RAG workflow, including:

- **Next.js Server**: Frontend layer handling user interaction and API routing.
- **FastAPI Server**: Backend API gateway that exposes endpoints to control RAG processes.
- **Endpoint Layer**: A microservices block for scrape, load, question, and delete operations.
- **LLaMA 3.2**: Local LLM that answers questions using retrieved vector documents.

---

## 🔄 Data Flow

### 👤 **User Interaction**

1. The user submits queries through the Next.js frontend.
2. Queries are forwarded to the FastAPI backend for processing.
3. Responses (answers) are returned to the user after being generated by the LLM.

---

## ⚙️ Service Responsibilities

### 📎 Next.js Server

- Acts as the UI layer.
- Sends API requests to the FastAPI server.
- Displays results from LLM responses.

---

### 🚀 FastAPI Server

Handles endpoints:

- `/scrape`: Triggers document scraping.
- `/load_data`: Reads and vectorizes documents.
- `/question`: Handles user input for LLM querying.
- `/delete`: Removes vector documents.

---

### 🧩 Endpoint Layer

#### 1. **Scrape Service**

- Scrapes Snowflake documentation.
- Saves raw files to a local folder.

#### 2. **Load Data Service**

- Reads downloaded Snowflake documentation.
- Converts documents into vector embeddings.
- Stores vectorized data into MongoDB.

#### 3. **Question Service**

- Accepts user input.
- Vectorizes the query.
- Retrieves the top 5 closest vectors from MongoDB.
- Feeds context + question into LLaMA.
- Returns the answer.

#### 4. **Delete Service**

- Deletes specific documents from MongoDB.
- Useful for purging stale or irrelevant vectors.

---

### 🧠 LLaMA 3.2 (LLM)

- Locally hosted.
- Consumes query + context to generate answers.
- Integrated with the Question endpoint.

---

## 🗃️ Data Storage

### 🧭 MongoDB

- Stores vectorized documents from Snowflake documentation.
- Supports:
  - `insert` (via Load Data),
  - `query` (via Question),
  - `delete` (via Delete).

## 🔄 API Workflow Summary

| Endpoint     | Description                             | Handler          |
| ------------ | --------------------------------------- | ---------------- |
| `/scrape`    | Scrapes docs from Snowflake             | Scrape Service   |
| `/load_data` | Vectorizes and stores docs in MongoDB   | Load Data        |
| `/question`  | Answers user queries using RAG pipeline | Question Service |
| `/delete`    | Deletes selected docs from DB           | Delete Service   |

## ✅ Key Features

- **Modular Microservices**: Each task in the pipeline is broken into composable services.
- **Vector Search with MongoDB**: Efficient document retrieval.
- **Local LLM (LLaMA 3.2)**: Ensures data privacy and low-latency inference.
- **Easy Extensibility**: Swap Snowflake docs with other datasets with minimal code change.

## 📦 Docker Compose Setup

All services run in isolated containers via Docker Compose. The `docker-compose.yml` file includes:

- Next.js frontend
- FastAPI backend
- MongoDB
- Optional volume bindings for document storage
- LLaMA model hosting

## 🔐 Security & Scaling Notes

- Secure API routes using token-based auth.
- MongoDB should be protected with access control.
- Consider LLaMA hosting alternatives (like inference endpoints) for scaling.
- Log and monitor endpoints for abuse or overload.
